# Spark side of the remote Kimodo lane: what kimodo_service.py needs, in its own venv
# at remote_kimodo_service/venv ON THE SPARK (`kaspar`, aarch64, GB10, CUDA 13).
# Never on Windows: this is the torch/GPU stack the Windows venv must not have.
#
# Create it (Malte, in the SSH session; read-only for Claude):
#
#   cd ~/project_kaspar/modules/kai-avatar-animation/remote_kimodo_service
#   python3 -m venv venv
#   venv/bin/python -m pip install --upgrade pip setuptools wheel
#   # 1. torch FIRST, the CUDA build. A plain resolver run can pull a CPU-only wheel.
#   #    torch 2.13.0 from PyPI is the CUDA 13 aarch64 build the working venv uses.
#   venv/bin/python -m pip install torch==2.13.0
#   venv/bin/python -c "import torch; print(torch.version.cuda, torch.cuda.is_available())"   # 13.0 True
#   # 2. kimodo: NOT from the git URL. Its MotionCorrection C++ extension needs the local
#   #    aarch64 patches (sse2neon.h, SIMD.h, CMakeLists.txt) in ~/kimodo-src. Its build
#   #    backend is setuptools, which --no-build-isolation takes from this venv.
#   venv/bin/python -m pip install --no-build-isolation ~/kimodo-src
#   # 3. then this file:
#   venv/bin/python -m pip install -r requirements.txt
#
# Start the service with it:   venv/bin/python kimodo_service.py
#
# Until this venv exists, the old one still works (it is untracked, so moving
# pipeline-network-osc/ to _old/ left it where it was):
#   ../pipeline-network-osc/venv/bin/python kimodo_service.py
